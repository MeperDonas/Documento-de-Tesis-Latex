RF01 – Autenticación y control de sesión

Prioridad: Alta
Código del requerimiento: RF01
Actor: Administrador / Usuario
Nombre del requerimiento: Autenticación y control de sesión

Descripción:
El sistema debe gestionar el acceso seguro de los usuarios mediante credenciales y mecanismos de control de sesión basados en tokens.

Funcionalidad:
El sistema debe validar las credenciales de acceso (correo y contraseña) contra la base de datos antes de permitir el ingreso del usuario.
El sistema debe generar un token de sesión (por ejemplo, JWT) para mantener la autenticación del usuario durante su navegación por el sistema.
El sistema debe restringir el acceso a las rutas internas únicamente a usuarios que posean un token de sesión válido y no expirado.

Criterios de aceptación:
1. El sistema debe permitir que el usuario ingrese su correo y contraseña en un formulario seguro (canal cifrado).
2. El sistema debe redirigir al dashboard principal cuando las credenciales sean válidas y el token se genere correctamente.
3. El sistema debe bloquear y redirigir a la pantalla de inicio de sesión cuando se intente acceder a recursos internos sin un token válido.

Restricciones:
El sistema debe almacenar las contraseñas encriptadas en la base de datos utilizando algoritmos de hashing seguros.

RF02 – Gestión del catálogo de productos (CRUD)

Prioridad: Alta
Código del requerimiento: RF02
Actor: Administrador
Nombre del requerimiento: Gestión del catálogo de productos

Descripción:
El sistema debe permitir la administración completa del catálogo de productos comercializados, garantizando la unicidad de identificadores y la disponibilidad inmediata de la información.

Funcionalidad:
El sistema debe permitir crear, leer, actualizar y desactivar productos, capturando como mínimo: nombre, SKU, código de barras, categoría, precio de costo, precio de venta, impuesto aplicable y stock actual.
El sistema debe validar que el SKU y el código de barras de un producto sean únicos dentro del catálogo.
El sistema debe aplicar eliminación lógica (borrado lógico) a los productos con ventas históricas, evitando la pérdida de información asociada.

Criterios de aceptación:
1. El sistema debe mostrar un mensaje de error cuando se intente registrar un producto con un SKU o código de barras ya existente.
2. El sistema debe mostrar el producto recién creado o actualizado de forma inmediata en el listado general de inventario.
3. El sistema debe impedir la eliminación física de productos que tengan ventas asociadas, permitiendo únicamente su desactivación.

Restricciones:
El sistema debe manejar paginación en el listado de productos cuando el número de registros supere el límite establecido.

RF03 – Registro de movimientos de stock

Prioridad: Alta
Código del requerimiento: RF03
Actor: Administrador / Usuario de inventario
Nombre del requerimiento: Registro de movimientos de inventario

Descripción:
El sistema debe mantener la trazabilidad de las variaciones de inventario distintas a las ventas, mediante el registro estructurado de movimientos de entrada y salida.

Funcionalidad:
El sistema debe registrar entradas y salidas de inventario clasificándolas por tipo (compra, ajuste, daño, devolución u otros definidos).
El sistema debe actualizar en tiempo cercano al real el stock disponible del producto según la cantidad registrada en cada movimiento.
El sistema debe almacenar para cada movimiento la fecha, la hora, el tipo de movimiento, el usuario responsable y una justificación.

Criterios de aceptación:
1. El sistema debe impedir registrar movimientos de salida que dejen el stock resultante en un valor negativo.
2. El sistema debe reflejar inmediatamente en la ficha del producto el nuevo stock disponible tras registrar un movimiento.
3. El sistema debe permitir consultar el historial de movimientos por producto y por rango de fechas.

Restricciones:
El sistema debe tratar cada movimiento como irreversible una vez confirmado; para corregir errores se debe generar un contra-movimiento con signo contrario.

RF04 – Alertas de stock bajo

Prioridad: Media
Código del requerimiento: RF04
Actor: Sistema / Administrador / Usuario de inventario
Nombre del requerimiento: Alertas de stock bajo y umbral mínimo

Descripción:
El sistema debe notificar de forma proactiva sobre productos cuyo nivel de existencias se encuentre por debajo del umbral mínimo configurado, facilitando la toma de decisiones de reabastecimiento.

Funcionalidad:
El sistema debe permitir configurar un umbral mínimo de stock por producto.
El sistema debe identificar y marcar como "stock bajo" los productos cuyo stock actual sea inferior o igual al umbral configurado.
El sistema debe resaltar visualmente los productos con stock bajo en el listado de inventario y/o en el dashboard principal.

Criterios de aceptación:
1. El sistema debe recalcular las alertas de stock automáticamente cada vez que se registre una venta o un movimiento de inventario.
2. El sistema debe resaltar claramente los productos en condición de stock bajo mediante iconos, colores o etiquetas diferenciadas.
3. El sistema debe permitir que el usuario modifique el umbral mínimo de un producto y que la alerta se actualice en consecuencia.

Restricciones:
El sistema no debe generar alertas para productos marcados como inactivos.

RF14 – Gestión de imágenes de productos

Prioridad: Media
Código del requerimiento: RF14
Actor: Administrador
Nombre del requerimiento: Gestión de imágenes de productos

Descripción:
El sistema debe permitir la carga, visualización y eliminación de imágenes asociadas a los productos del catálogo, mejorando la identificación visual en el punto de venta y en los reportes.

Funcionalidad:
El sistema debe permitir cargar imágenes de productos en formatos JPG, PNG o WEBP con un tamaño máximo de 5MB.

2. El sistema debe mostrar una vista previa de la imagen antes de confirmar su guardado.
3. El sistema debe mostrar la imagen del producto en el módulo de punto de venta y en el comprobante de venta.

Restricciones:
El sistema debe implementar mecanismos de seguridad para prevenir la carga de archivos maliciosos disfrazados como imágenes.

RF15 – Búsqueda y filtrado avanzado de productos

Prioridad: Alta
Código del requerimiento: RF15
Actor: Administrador / Cajero
Nombre del requerimiento: Búsqueda y filtrado avanzado de productos

Descripción:
El sistema debe proporcionar capacidades de búsqueda y filtrado avanzadas para localizar productos rápidamente en el catálogo mediante múltiples criterios combinables.

Funcionalidad:
El sistema debe permitir buscar productos por nombre, SKU, código de barras o categoría de forma individual o combinada.
El sistema debe implementar búsqueda incremental que muestre resultados mientras el usuario escribe.
El sistema debe permitir filtrar productos por rango de precios, estado (activo/inactivo) y nivel de stock (normal, bajo, agotado).
El sistema debe ordenar los resultados por nombre, precio, stock o fecha de creación en orden ascendente o descendente.

Criterios de aceptación:
1. El sistema debe mostrar resultados de búsqueda en menos de 2 segundos para catálogos de hasta 10,000 productos.
2. El sistema debe resaltar visualmente los términos de búsqueda coincidentes en los resultados mostrados.
3. El sistema debe mantener activos los filtros aplicados al navegar entre páginas de resultados.

Restricciones:
La búsqueda debe ser insensible a mayúsculas, minúsculas y acentos para mejorar la experiencia del usuario.

RF05 – Procesamiento de venta en tiempo real

Prioridad: Alta
Código del requerimiento: RF05
Actor: Cajero / Administrador
Nombre del requerimiento: Procesamiento de venta en tiempo real

Descripción:
El sistema debe proporcionar una interfaz ágil para la ejecución de ventas, permitiendo la selección de productos, el cálculo automático de totales y el registro de la transacción con impacto inmediato en el inventario.

Funcionalidad:
El sistema debe permitir buscar productos por nombre, SKU o código de barras y agregarlos a un carrito de venta con la cantidad correspondiente.
El sistema debe calcular automáticamente el subtotal, el valor del impuesto y el total final de la venta según los datos del catálogo.
El sistema debe registrar la venta con un identificador único, fecha, hora, usuario, productos vendidos, cantidades, totales y cliente asociado (cuando aplique).

Criterios de aceptación:
1. El sistema debe impedir confirmar una venta cuando al menos uno de los productos no disponga de stock suficiente.
2. El sistema debe mostrar al usuario un resumen detallado de la venta antes de su confirmación.
3. El sistema debe completar el registro de la venta y dejarla disponible para consulta en el historial de ventas inmediatamente después de su confirmación.

Restricciones:
La interfaz de venta debe minimizar el número de clics necesarios para completar una transacción típica en el punto de venta.

RF06 – Gestión de métodos de pago y cálculo de cambio

Prioridad: Alta
Código del requerimiento: RF06
Actor: Cajero / Administrador
Nombre del requerimiento: Gestión de métodos de pago y cálculo de cambio

Descripción:
El sistema debe manejar diferentes métodos de pago y calcular el cambio a devolver al cliente cuando el pago se realice en efectivo.

Funcionalidad:
El sistema debe permitir seleccionar el método de pago para cada venta (efectivo, tarjeta, transferencia u otros definidos).
El sistema debe permitir ingresar el monto entregado por el cliente en caso de pago en efectivo y calcular automáticamente el cambio a devolver.
El sistema debe registrar el método de pago y los valores asociados en el detalle de la venta para su posterior análisis.

Criterios de aceptación:
1. El sistema debe validar que el monto entregado por el cliente en efectivo sea igual o superior al total de la venta.
2. El sistema debe mostrar de forma clara el valor del cambio a devolver antes de finalizar la transacción.
3. El sistema debe permitir filtrar ventas por método de pago en los reportes y consultas.

Restricciones:
Los métodos de pago disponibles deben ser configurables únicamente por usuarios con permisos de administración.

RF07 – Descuento automático de inventario por venta

Prioridad: Alta
Código del requerimiento: RF07
Actor: Sistema / Cajero / Administrador
Nombre del requerimiento: Actualización automática de stock por venta

Descripción:
El sistema debe actualizar automáticamente las existencias de los productos involucrados en una venta al momento de confirmar la transacción, manteniendo la consistencia con el módulo de inventario.

Funcionalidad:
El sistema debe descontar del stock de cada producto la cantidad vendida cuando una venta se confirme exitosamente.
El sistema debe registrar un movimiento de inventario de tipo "salida por venta" asociado al identificador de la venta.

1. El sistema debe mostrar el nuevo stock disponible del producto inmediatamente después de confirmar la venta.
2. El sistema debe impedir la confirmación de la venta si no se logra aplicar correctamente el descuento de inventario.
3. El sistema debe permitir consultar, desde la ficha de un producto, los movimientos de salida generados por ventas.

Restricciones:
La operación de registro de venta y descuento de inventario debe ejecutarse de forma atómica para evitar inconsistencias.

RF08 – Generación de comprobantes de venta

Prioridad: Media
Código del requerimiento: RF08
Actor: Cajero / Administrador
Nombre del requerimiento: Emisión de comprobantes de venta

Descripción:
El sistema debe generar un comprobante documental de cada venta realizada, disponible en formato imprimible o digital, para soporte del cliente y del negocio.

Funcionalidad:
El sistema debe generar automáticamente un comprobante al finalizar exitosamente una venta, incluyendo: logo del negocio, fecha, número de venta, datos del cliente (si aplica), detalle de ítems, impuestos, total y método de pago.
El sistema debe permitir la visualización del comprobante desde el navegador y su impresión directa o descarga en formato digital (por ejemplo, PDF).
El sistema debe manejar un consecutivo incremental y único para la numeración de las ventas.

Criterios de aceptación:
1. El sistema debe generar el comprobante inmediatamente después de finalizar la venta sin requerir acciones adicionales del usuario.
2. El sistema debe presentar el comprobante en un formato compatible con impresoras de tirilla y/o tamaño carta, según configuración.
3. El sistema debe permitir recuperar y volver a imprimir o descargar el comprobante desde el historial de ventas.

Restricciones:
El diseño del comprobante debe ajustarse a los formatos definidos por la configuración del negocio y las normas vigentes aplicables.

RF09 – Anulación y devolución de ventas

Prioridad: Media
Código del requerimiento: RF09
Actor: Administrador
Nombre del requerimiento: Gestión de anulaciones y devoluciones

Descripción:
El sistema debe permitir gestionar anulaciones totales y devoluciones parciales de ventas, ajustando en consecuencia el inventario y los registros históricos.

Funcionalidad:
El sistema debe permitir seleccionar una venta registrada y marcarla como anulada o registrar la devolución de uno o varios productos.
El sistema debe generar los movimientos de inventario necesarios para revertir total o parcialmente el descuento de stock asociado a la venta original.
El sistema debe registrar la fecha, el usuario responsable y el motivo de la anulación o devolución.

Criterios de aceptación:
1. El sistema debe reflejar el ajuste del inventario derivado de la anulación o devolución en el stock de los productos afectados.
2. El sistema debe mantener visible en el historial la venta original con un estado que indique "anulada" o "con devolución".
3. El sistema debe impedir la anulación de ventas cuando existan restricciones adicionales configuradas (por ejemplo, cierres de caja o cierres contables).

Restricciones:
Solo usuarios con permisos de administración pueden ejecutar procesos de anulación o devolución.

RF16 – Aplicación de descuentos en ventas

Prioridad: Alta
Código del requerimiento: RF16
Actor: Cajero / Administrador
Nombre del requerimiento: Aplicación de descuentos en ventas

Descripción:
El sistema debe permitir aplicar descuentos porcentuales o en valor fijo sobre items individuales o sobre el total de la venta, con el objetivo de facilitar promociones y ajustes comerciales.

Funcionalidad:
El sistema debe permitir aplicar descuentos de tipo porcentual (%) o valor fijo ($) a items individuales en el carrito de venta.
El sistema debe permitir aplicar un descuento general sobre el subtotal de la venta completa.
El sistema debe recalcular automáticamente el subtotal, impuestos y total de la venta al aplicar o modificar descuentos.
El sistema debe registrar en el detalle de la venta los descuentos aplicados con su tipo, monto y justificación.

Criterios de aceptación:
1. El sistema debe validar que los descuentos porcentuales se encuentren entre 0% y 100%.
2. El sistema debe impedir aplicar descuentos que resulten en un total de venta negativo.
3. El sistema debe mostrar claramente en el comprobante de venta los descuentos aplicados y el ahorro obtenido por el cliente.

Restricciones:
El sistema debe requerir autorización mediante contraseña de administrador para descuentos superiores al 30% del valor del item o de la venta total.

RF17 – Gestión del carrito de compras temporal

Prioridad: Alta
Código del requerimiento: RF17
Actor: Cajero
Nombre del requerimiento: Gestión del carrito de compras temporal

Descripción:
El sistema debe permitir gestionar items en un carrito de compras antes de confirmar la venta, facilitando modificaciones de cantidad, eliminación de productos y cálculos dinámicos.

Funcionalidad:
El sistema debe permitir agregar productos al carrito especificando la cantidad deseada.

RF18 – Consulta de ventas por rango de fechas

Prioridad: Media
Código del requerimiento: RF18
Actor: Administrador
Nombre del requerimiento: Consulta de ventas por rango de fechas

Descripción:
El sistema debe permitir consultar el historial de ventas realizadas filtrando por un rango de fechas específico, facilitando análisis de períodos comerciales y auditorías.

Funcionalidad:
El sistema debe permitir seleccionar una fecha de inicio y una fecha de fin para delimitar el período de consulta.

Las consultas de rangos superiores a un año deben implementar paginación para optimizar el rendimiento del sistema.

Prioridad: Media
Código del requerimiento: RF12
Actor: Administrador
Nombre del requerimiento: Dashboard de indicadores y reporte histórico filtrable

Descripción:
El sistema debe ofrecer una vista ejecutiva del estado del negocio mediante indicadores clave y reportes históricos de ventas con filtros avanzados.

Funcionalidad:
El sistema debe calcular y mostrar en el dashboard métricas clave como ventas del día, ventas del mes, número de transacciones y número de productos con stock bajo.
El sistema debe permitir generar reportes históricos de ventas filtrables por rango de fechas, cliente, producto y método de pago, presentando el detalle de cada transacción.

3. El sistema debe presentar un resumen con el margen promedio general del negocio.

Restricciones:
